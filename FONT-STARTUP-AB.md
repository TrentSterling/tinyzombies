# Tiny Zombies: font stylesheet startup A/B

Compare commit 23ee4e77f1700a3ea1d8682e3d22312ccdcdfb60 (index blob 4bc08562d14041d02fcb4456881dcca10c7452dc) with this branch. The candidate requests the same Google Fonts CSS from JavaScript instead of making it a parser-created stylesheet. Boot/game CSS, fonts, fallbacks, step pacing and gameplay are otherwise unchanged. Source/VM tests are not a browser benchmark.

1. Use separate complete checkouts served from the same origin, same foreground browser, viewport, hardware WebGPU adapter and options (`?sandbox&seed=73129&horde&tier=0&msaa=4`). Instrument both with the same [browser A/B harness](https://github.com/TrentSterling/tinyzombies/blob/db0c196db3f3d324c3fdcdd00c38d07e913d9c63/tools/BROWSER-PERF.md). Add `performance.mark('tiny-script-entry')` immediately after the game's strict directive in both test copies, before any other injected work there.
2. Before navigation, set up a hold for only the Google Fonts CSS URL, for example 2 seconds from its request; release it in each variant without changing the response. Start timing at navigation. Use first-contentful-paint, the script mark, the first `startupWork` step and completion, and `readyMs`. Observe whether the fallback loader is visible and progressing while the request is still pending. Do not use `window.load` or `DOMContentLoaded` as the start or the ready signal.
3. Repeat with the CSS request failed and with ordinary cold and warm caching. Keep the conditions separate, alternate paired run order, and record the request timing and any browser/CSP errors. Verify the exact step count, percentage and ready status still agree.
4. Check loader/title/HUD alignment and legibility at normal and narrow viewports with CSS pending or failed, then verify Bangers and Rubik actually load and render on successful release. Inspect matching loaded FontFace entries and compare before/after visuals; a CSS 200 or a computed family list alone is not proof the font rendered. Check that existing Canvas text measurement updates when the fonts become available.

Don't use a forced network hold to estimate the speedup on a normal connection. If normal runs do not improve, describe the benefit as avoiding stalls on slow or blocked font connections. Do not ship on the source checks alone.
