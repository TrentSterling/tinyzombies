# Tiny Zombies browser A/B

Compare the original live commit `77486f01d37ac14a58e02bf2a8a1ad2720475f74` (index blob `230784f04a35cb07f7f5fee62776c158d64cbe30`) with the combined candidate `471cf3d01429cef53c6ac879a47c1bee3f42031d` (blob `e1049a98e05e48d43b814435377b81178ea77e4e`). Create separate complete checkouts so the local copies load their normal relative assets. In the harness checkout, run `node tools/browser-perf.cjs <checkout>/index.html <checkout>/perf-local.html` for each checkout. It prints the original blob hash and refuses to overwrite existing files. Serve both directories from the same localhost HTTP origin at different paths. This doesn't modify the deployed page.

- Use the same real hardware/browser, hardware WebGPU adapter, viewport, refresh rate, browser zoom, and foreground state. Use `?sandbox&seed=73129&horde&tier=0&msaa=4` for both; repeat at a low-quality preset with `tier=3&msaa=1` on both. Confirm the reported configuration (rendered width, height, MSAA, capacity, started, paused, seed, stage) stays constant during the compared slice. Discard attempts with hidden tabs, resizes, or device loss. No `lab`, which would change the horde.
- Cold load: use fresh browser profiles for cold shader/HTTP caches; alternate A/B order. Record `__tinyPerf.readyMs` and separately first frame submission after Play (a navigation-relative timestamp, not GPU completion). Keep voice/audio in the same state. Measure the first 10 seconds after Play separately from steady play so post-click audio decoding is not mistaken for initial load.
- Frame pacing: call `__tinyPerf.start()` in DevTools, close or undock DevTools, then play the same rescue-to-breach route with the same game inputs. Stop with `copy(__tinyPerf.stop())` in Chrome DevTools. Save raw rows and compare per-run p50/p95/p99/worst and skipped-callback counts over comparable windows. Raw intervals are elapsed rAF timestamps **between submitted frames**, not display or GPU completion times. Don't treat skipped callbacks as zero-time samples. Record route, start/end event, and breach confirmation alongside results. Manual repeats are not deterministic; use matched route, duration, and horde pressure, and save unsuccessful attempts separately.
- GPU stages: a separate `__tinyPerf.start('gpu')` capture rotates sampling through nav phases 0–15. Check every phase has samples; if unsupported, the GPU array stays empty. `relaxMs` covers relaxation and, on the candidate, its convergence check, not nav init/publication. World excludes drip. Total ends at tone map/HUD, before actor readback; `actorRead` and `drip` are flags, not timings. Compare by phase and drip flag; do not infer cost for work outside the timestamps. Stop again if a sample is still pending.
- For automated comparison, note raw frame tuples are `[rafMs, deltaMs, frame, navPhaseBeforeSimulation, width, height, msaa, capacity, started, paused, seed, stage]`. For the manual capture, use enough lead-in/tail-out to trim the DevTools activity and align the same events for A/B. Avoid `controlledStep()` for FPS: it serializes GPU submission and does not render.
