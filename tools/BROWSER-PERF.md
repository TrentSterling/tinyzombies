- Use the same real hardware/browser, hardware WebGPU adapter, viewport, refresh rate, browser zoom, and foreground state. Use `?sandbox&seed=73129&horde&tier=0&msaa=4` for both; repeat at a low-quality preset with `tier=3&msaa=1` on both. Confirm the reported configuration (rendered width, height, MSAA, capacity, started, paused, seed, stage) stays constant during the compared slice. Discard attempts with hidden tabs, resizes, or device loss. No `lab`, which would change the horde.
- Cold load: use fresh browser profiles for cold shader/HTTP caches; alternate A/B order. Record `__tinyPerf.readyMs` (navigation to ready) separately from `acceptedPlayToFirstSubmitMs` in the stopped capture. The latter runs from the first accepted initial canvas Play click to the first started frame submission, excluding the human wait on the ready screen. It is null if no accepted click or no started submission was observed. `acceptedPlayMs` and `firstStartedSubmitMs` remain navigation-relative timestamps. Neither submission metric is GPU completion, presentation, or input-to-photon time. Use a fresh navigation for each startup attempt, since these first-event timestamps do not reset with capture start/stop. `startupWork` records key, label, start/end, duration and completed/failed status around the actual awaited work, after forced paint waits. Those durations exclude scheduler paint waits but include asynchronous waits within work, not just CPU execution. Keep voice/audio in the same state. Measure the first 10 seconds after Play separately from steady play so post-click audio decoding is not mistaken for initial load.
- Frame pacing: call `__tinyPerf.start()` in DevTools, close or undock DevTools, then play the same rescue and fresh-restart breach slices with the same game inputs. Keep the audio/director settings matched: these affect whether the game requests actor readbacks. Stop with `copy(__tinyPerf.stop())` in Chrome DevTools. Save raw rows and compare per-run p50/p95/p99/worst and skipped-callback counts over comparable windows. Raw intervals are elapsed rAF timestamps **between submitted frames**, not display or GPU completion times. Don't treat skipped callbacks as zero-time samples. Record route, start/end event, and breach confirmation alongside results. Manual repeats are not deterministic; use matched route, duration, and horde pressure, and save unsuccessful attempts separately.
- Normal frame captures and periods without a capture retain the shipping every-30-frame timestamp query/readback cadence and its overhead. Rotating sample scheduling is enabled only in explicit GPU mode. Do not compare old harness frame captures (which omitted stock stamps) with this harness version as if instrumentation were identical.
- GPU stages: a separate `__tinyPerf.start('gpu')` capture rotates sampling through nav phases 0–15. Check every phase has samples; if unsupported, the GPU array stays empty. `relaxMs` covers relaxation and, on the candidate, its convergence check, not nav init/publication. World excludes drip. Total ends at tone map/HUD, before actor readback; `actorRead` and `drip` are flags, not timings. Compare by phase and drip flag; do not infer cost for work outside the timestamps. Stop again if a sample is still pending.
- Actor readback: `actorReadbacks` reports submitted zombie and prop bytes separately. `submitToMapReadyMs` runs from the return of queue submission to the observed map promise callback; it includes queueing, earlier work, mapping and event-loop delay, not GPU transfer alone. `cpuCopyMs` covers the two actor/prop mapped-range reads and typed-array copies only, not state copies, audio processing or the whole callback. Normal actor submissions are `copied`; `discarded` marks reset/reseed, `map-error` or `read-error` marks failure, and `pending` means incomplete at capture stop. Null does not mean zero. No additional readback or wait is inserted.
- `intervalMsAfterSubmission` groups each elapsed submitted-frame interval by the **preceding** submission: actor payload, state/counters only, or no read. The last submitted frame contributes no subsequent interval. This is correlation, not causation: map callbacks can arrive later, and nav, drip and timestamps can overlap.
- For automated comparison, note raw frame tuples are `[rafMs, deltaMs, frame, navPhaseBeforeSimulation, width, height, msaa, capacity, started, paused, seed, stage, sampleKind]`. For the manual capture, use enough lead-in/tail-out to trim the DevTools activity and align the same events for A/B. Avoid `controlledStep()` for FPS: it serializes GPU submission and does not render.

## Seed 73129 qualification route

Use the exact pairs listed above. A four-build parse check confirms hook compatibility only, not runtime performance or gameplay equivalence. The route and target below were checked against static map data, not played through. Use the same ordinary controls on each version.

1. **First Play:** Capture separately from navigation-to-ready and from the rescue. Keep audio on and settings identical unless deliberately measuring the muted case; don't mix the two cases.
2. **Rescue:** Start at safe room `(-64,52)` in X/Z. Open its door at `(-60.25,52)` with E and cross to `(-59.25,52)`. The static collision guide to Brenda is `(-59.625,56.25)` → `(-59.875,56.375)` → `(-71.5,61.625)` → `(-71.75,61.875)` → `(-75.5,61.875)` → `(-79.25,58.125)` → `(-85.375,58.125)`. Accept the paired run only with an observed join and save; track lost or diverted attempts separately. The already-sampled counters in `__tiny.stats` are indexed 96 (joined), 97 (lost), and 98 (saved). Read them outside the measured slice if checking them through DevTools.
3. **Breach:** Fresh restart, same weapon and starting position. Aim at chest height from the safe-room center toward the wall near X/Z `(-64,48)`. Static ray target: block 73406 at `(-63.875,0.625,48.375)`, 8 HP. Verify actual aim and wall damage in play, then record the shot sequence and visible opening. A confirmed first voxel hit alone is not a breach. Don't run `readWorld()` during timing; it inserts a separate GPU readback.
